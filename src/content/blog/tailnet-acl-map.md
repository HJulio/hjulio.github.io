Tailscale ACLs are a JSON file. That is great for version control and terrible for answering the only question anyone ever asks about them: *who can reach this box, and on which ports?* Once you have a handful of groups, a few tags, an ipset and some subnet routers, reading the policy top to bottom stops working. You end up tracing `group:` into `grants` into `host:` into `hosts` with your finger on the screen.

I wanted a picture. So I built one: **[Tailnet ACL Map](https://hache.xyz/tailnet-acl-map/)**. You paste your policy, it draws the graph. Source is on [GitHub](https://github.com/HJulio/tailnet-acl-map).

![People, groups and destinations drawn as a three-column graph, with the allowed ports on each edge](/static/tailnet-acl-map/graph.png)

## What it shows

- **The graph.** People on the left, sources in the middle (groups, direct per-user rules, tags), destinations on the right. Each edge carries its ports. Orange means `*`, green means a restricted port list, dashed means a group no rule uses. Hover or tap a node to isolate its paths.
- **Group membership matrix.** People against groups, with the number of grants each group actually has. A group with zero grants is a group you can delete.
- **Per-person reach.** For every login, the flattened list of what they can get to. This is the table I actually wanted; the graph is how you check it.
- **Tailscale SSH, tag owners and hosts.** Who can SSH where and as which user, which tags have no owners (so only the admin console can apply them), and which host aliases nothing references.
- **Findings.** Things the policy does not say out loud: groups nobody grants anything to, users outside any group, wildcard grants, Funnel enabled for everyone, and CIDR overlaps. The overlap check is the one that paid for the whole exercise: in my own tailnet, five `/32` hosts that a vendor group reaches on four ports sit inside a `10.0.0.0/8` that another group reaches on every port. The policy never puts those two facts next to each other. The map does.
- **Problems.** Parse errors with line and column, octets above 255, prefixes longer than 32, CIDRs with host bits set, ports above 65535, reversed ranges, references to groups, hosts, ipsets or tags that are never defined, legacy `acls` destinations without a port suffix, groups that contain groups.

![The Problems section listing ten errors and six warnings for a deliberately broken policy](/static/tailnet-acl-map/problems.png)

## How it works

It is one `index.html`. No build step, no dependencies, no backend. Parsing and rendering happen in your browser and the policy never leaves it, which matters when the input is a complete description of your private network.

The pipeline is short:

1. **HuJSON to JSON.** Tailscale policies allow `//` and `/* */` comments and trailing commas. A small state machine blanks comments out with spaces instead of deleting them, so when `JSON.parse` fails the reported position still maps to the line and column you pasted.
2. **Policy to rules.** `grants`, legacy `acls` and `ssh` entries are normalised into the same shape: a list of sources, a list of destinations, a port label. `ipset:` references expand to their hosts; `host:` aliases resolve to their CIDR.
3. **Rules to graph.** Sources that are groups get their members as edges from the people column. Each rule becomes an edge from source to destination with a port pill in the middle. The SVG is generated by about sixty lines of DOM calls; column widths come from the longest label, pills are spread along the curve and nudged apart when they collide.
4. **Findings.** Mostly set operations over the same model. The CIDR check is the only real arithmetic:

```js
const inside = (a, b) => b.bits < a.bits && ((a.n ^ b.n) >>> (32 - b.bits)) === 0;
```

Two addresses as 32-bit integers, XOR them, shift away the host part of the wider prefix. If nothing is left, the narrow one is inside the wide one.

## Testing it against other people's policies

My own ACL is one data point. To find out whether the thing held up, I pointed it at every public policy I could find: the samples in the Tailscale docs (ACL syntax, ACL samples, grants, Tailscale SSH) and the 125-policy test corpus that [headscale](https://github.com/juanfont/headscale) keeps, which includes deliberately malformed files. A Playwright loop pasted each one into the page and checked for JavaScript errors, text overflowing its box, overlapping port labels and empty graphs.

That run found four real bugs in an afternoon's worth of code: port labels overlapping when two rules had neighbouring destinations, SSH-only policies rendering an empty graph, bare host aliases (legal in legacy `acls` without the `host:` prefix) not resolving, and hosts referenced only through an ipset showing as unused. All fixed, and the malformed headscale fixtures now light up the Problems section the way they should: a phantom group, an unknown autogroup, an empty source.

## What a three-model review found

Before calling it done I ran the same review brief through three models independently: Claude, Codex and Gemini, each told to review `index.html` alone, with two hard invariants. The app must never claim access the policy does not grant, and no pasted string may reach the DOM unescaped.

They agreed on the second invariant: every interpolation goes through an escape function. On the first they all came back with **changes requested**, and the overlap between them was high enough to trust:

- A legacy `acls` rule with several destinations on different ports, such as `["web:80", "db:5432"]`, is drawn as one destination with the union of ports. That is a cross-product the policy never granted.
- A grant with `app` capabilities and no `ip` is shown as all ports. Tailscale treats a missing `ip` as all ports only when `app` is also missing.
- The "all ports" test is written four different ways across the file, and `["*", "tcp:22"]` ends up classified as restricted.
- `remove` entries in an `ipset` are ignored instead of subtracted, so the set looks wider than it is.
- The containment check fails for `/0` because in JavaScript a shift by 32 is a shift by 0.
- The trailing-comma regex also runs inside string literals.

Each model also found something the other two missed: Codex saw the `acls` cross-product and questioned drawing SSH rules in a network-access graph at all; Claude found the ipset `remove` case and that an IPv6 destination without a port slips through validation; Gemini noticed a crash path when `nodeAttrs.target` is not an array. I verified every one against the code before accepting it, and none of the three produced a false positive worth arguing about.

At the time of writing those are the known issues. Until they are fixed, treat the per-person table and the overlap findings as a prompt to go read the rule, not as the final word.
